## Implementation and review boundaries

Production browse routes no longer use the illustrative property catalogue. Home uses up to twelve available public records, desktop featured cards use three, and search renders server-returned pages and totals on desktop/mobile. A genuine empty database shows an empty state. SSR detail URLs resolve any eligible database slug; old static sample slugs are no longer prebuilt. Prices, charges, amenities, photos/videos, availability and verification data come from the public API. Existing fonts, brown/cream tokens, card links, dropdown/Other behavior, naira steps, app shell and launch flow are retained. Public gallery uses actual media, never another listing's picture. Reports/inquiries/assistant remain their existing separate unconnected modules.

Search applies the contract on the server. Dropdown locations/amenities come from active taxonomy, including options beyond the old three example areas. Other preferences remain free-text q. Bathroom filtering stays absent from the UI per the owner's direction, although the contract API still accepts bathrooms_min. Applying filters resets pagination. Direct URL queries preserve contract validation rather than silently ignoring unsupported filters. A narrow Next proxy checks property visibility before page streaming and returns a complete HTTP 404 response using existing not-found copy/logo and extracted design tokens; generateMetadata/page also independently handle 404. Metadata blocking and status-preserving rewrites were tested but did not fix this runtime streaming behavior, so the proxy returns the final status directly and the global config is unchanged. Reference: https://nextjs.org/docs/app/api-reference/file-conventions/loading (status codes).

All public asset reads check current eligibility and media ID. Documents never enter the public projection or media route. Local delivery uses FileResponse (including range support); existing S3 signing caps a redirect at sixty seconds. No public bucket, direct-upload grant, real file migration or CDN changes are included. Storage configuration is still required for hosted photos. A missing storage service does not prevent listing JSON from loading.

No schema migration was required: existing status/publication, price, area, current verification/approval and amenity indexes are reused. Query-plan evidence distinguishes a selective price query (index use) from a broad query (scans can be optimal when nearly all 5,000 rows qualify). No indexes are forced. Broad-search p95 measured with twenty warm local API requests is recorded below; it is not a Vercel/Render/4G or 5,000-property production claim.
