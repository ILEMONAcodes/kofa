## Implemented flow

Clients use `/account/inquiries`, property detail → Express interest, or `/account/general-inquiry`. Successful creation opens the actual saved conversation. The client overview now shows real inquiries rather than fictional counters. Staff/admin use `/staff/inquiries` and `/staff/clients`; the existing workspace menu links to the inbox. Staff can search/filter, assign active team members, reply, update qualification/status, and maintain separate private notes. Client directory detail includes recent inquiry history and confirmed deactivate/reactivate actions.

Text threads have pagination, refresh, 30-second polling while visible, server-owned unread counts and scoped read acknowledgements. Staff share team read state. Only incoming messages actually loaded through a specific ID are acknowledged; future/other-thread messages remain unread. Notes are separate from the reply composer and never appear in any client DTO. Inquiry IDs, status/actions, versions and receipt come from the backend. Cookie sessions, CSRF/Origin, same-origin transport, body caps and per-actor rate limits remain enforced. UI uses original brown/cream tokens, existing controls and Nigeria date/money formatters. Changing a record resets its form state.
